## High-level view

The v1 fix correctly sums all panel DC outputs before computing inverter efficiency in optimizer mode. The without-optimizers path was not similarly updated — it loops over strings and applies the efficiency curve to each string's DC power independently (`oblicz_sprawnosc_falownika(moc_dc_string, moc_nominalna_falownika_w)`). Because the denominator is the full inverter capacity, a multi-string installation will always see a lower load fraction per-string than the inverter actually experiences. At moderate irradiance this causes a few percent underestimation; at dawn/dusk it can push individual strings below the 2% startup threshold causing zero output even though the combined power is above it.

## Inverter efficiency asymmetry between optimizer and non-optimizer paths

The v1 fix at line 1002–1009 of `panel_performance.py` correctly accumulates all panel DC into `suma_dc` before calling the efficiency curve once:

```python
# Krok 2: oblicz sprawnosc falownika na podstawie sumarycznej mocy DC
suma_dc = sum(moc_dc_paneli)
if suma_dc > 0:
    eta = oblicz_sprawnosc_falownika(suma_dc, moc_nominalna_falownika_w)
    energia_godziny = suma_dc * eta
```

The without-optimizers branch (line 1044–1050) still applies per-string:

```python
moc_dc_string = moc_stc * n_paneli * (efektywna_irr / 1000.0) * wsp_temp_p * wsp_degradacji
if moc_nominalna_falownika_w and moc_nominalna_falownika_w > 0:
    eta = oblicz_sprawnosc_falownika(moc_dc_string, moc_nominalna_falownika_w)
```

For a 10-panel installation split into 2 strings of 5 on a 5kW inverter: each string produces ~2kW at midday (40% load → ~0.974 efficiency). The inverter actually sees 4kW (80% load → ~0.973 efficiency). The difference at midday is negligible. But at 200 W/m² each string produces ~400W (8% load → ~0.91 efficiency per string), while the aggregate 800W is at 16% load (~0.965). That's a 5% energy underestimation for each low-irradiance hour — dawn, dusk, and overcast days accumulate into a meaningful annual error.

The fix mirrors the optimizer path: accumulate all string DC totals, compute efficiency once, then scale proportionally.
