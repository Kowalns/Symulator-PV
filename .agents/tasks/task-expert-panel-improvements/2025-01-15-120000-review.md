# Six expert-panel physics and economics refinements for PV simulator

This change adds six interrelated improvements to the photovoltaic simulation engine: a string-level electrical model with mismatch losses, a net-billing deposit settlement mode, a lowered bypass diode activation threshold (50% → 15%), a load-dependent inverter efficiency curve replacing constant 3% losses, bifacial panel support with rear-side irradiance gains, and a seller margin deducted from energy sale price. The approach threads these features end-to-end — from database entries through hourly physics calculations to the economics layer and frontend UI — so they compose naturally in a single simulation run.

**Watch for:** The net-billing deposit function accepts a `magazyn` parameter but completely ignores it (confirmed), meaning battery storage has no effect in deposit mode. The `oblicz_wspolczynnik_zacienienia` docstring in `panel_performance.py` still documents the old 50% bypass threshold while the underlying shading service now uses 15% (confirmed, stale docs but not a runtime bug). The inverter efficiency curve is applied per-panel in optimizer mode rather than to the aggregate DC bus, which overstates clipping losses for small individual panel outputs (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

The string model divides panels into strings based on inverter MPPT voltage range, then applies per-string mismatch loss hourly. With optimizers each panel is independent; without them the worst-shaded panel (after bypass) limits its entire string. The division algorithm targets the midpoint of min/max panels-per-string and distributes panels evenly, with a fallback to a single string when MPPT constraints can't be satisfied — but the fallback silently produces an electrically invalid configuration without warning.

The net-billing deposit settlement accumulates surplus value into a PLN deposit account that offsets future grid purchase costs hour-by-hour. At year-end, 80% of the remaining balance is forfeited. The `magazyn` parameter is accepted in the function signature but never referenced in the body — a user selecting both deposit mode and battery storage gets silently incorrect results.

The inverter efficiency curve replaces the flat 3% system-loss constant with a piecewise model: zero output below 2% load, linear ramp through 85–97% between 2–20%, and a quadratic plateau peaking at 97.5% near 50%. The curve is applied individually to each panel's DC output in optimizer mode, which is physically incorrect for a shared inverter — the inverter sees the summed DC power from all panels, not individual contributions.

Bifacial support adds rear-side irradiance as GHI × albedo × bifacial coefficient × height factor, but the panel-to-ground clearance (`przeswit_nad_gruntem_m`) defaults to 0.5m and is never exposed to the user. Ground-mount bifacial installations (the primary use case) typically have 1.0–1.5m clearance.

The bypass threshold was lowered from 50% to 15% in both shading and optimizer, but the `oblicz_wspolczynnik_zacienienia` docstring still references the old 50% value.

## String model and inverter efficiency interaction

`podziel_na_stringi` computes `max_per_string = floor(Vmppt_max / Vmpp)` and `min_per_string = ceil(Vmppt_min / Vmpp)`, then targets the arithmetic midpoint. When `min > max` (incompatible panel/inverter pairing), it falls back to one string containing all panels — a configuration that would trip a real inverter's overvoltage protection. The fallback should emit a warning in the API response.

The inverter efficiency is applied per-panel when optimizers are active:

```python
for idx in sorted(wszystkie_indeksy):
    moc_dc = moc_stc * (efektywna_irr / 1000.0) * wsp_temp_p * wsp_degradacji
    eta = oblicz_sprawnosc_falownika(moc_dc, moc_nominalna_falownika_w)
```

A single 400W panel at 200 W/m² produces ~80W DC. Against a 5000W inverter that's 1.6% load — below the 2% startup threshold, so `eta = 0` and the panel produces nothing. In practice, all panels feed the same inverter simultaneously and the aggregate easily exceeds startup. The without-optimizers path correctly applies efficiency to the string's summed DC. Fix: sum all panel DC first, compute efficiency once on the total.

## Net-billing deposit: dead magazyn parameter and settlement timing

The `magazyn` parameter in the function signature is dead code — no battery charge/discharge logic exists in this path. The handler in `handlers.py` passes it through, meaning a user who selects both deposit mode and battery storage gets silently wrong results (battery has no effect).

The settlement fires at calendar year-end. Polish net-billing deposit rules define the 12-month window from the first surplus injection, not calendar-aligned. For a simulation always starting January this happens to be equivalent, but the assumption is undocumented and would break if the simulation ever supports mid-year start dates.

## Bypass threshold docstring inconsistency

The shading service (`shading.py:479`) activates bypass when `sekcja_stopien > 0.15`. The optimizer's mismatch function (`optimizer.py:206`) independently checks `pokrycie_procent > 0.15`. These are consistent with each other.

`oblicz_wspolczynnik_zacienienia` in `panel_performance.py:382` documents: "Bypass diody: jesli sekcja zacieniona >50%, bypass aktywuje sie". This function reads the pre-computed `bypass_aktywne` field (already computed with 15% threshold), so runtime behavior is correct. The stale docstring will mislead any developer reasoning about bypass sensitivity.

## Bifacial height not user-accessible

The height interpolation covers:

```
0.5m → 0.60
1.0m → 0.80
1.5m → 0.95 (cap)
```

The default 0.5m locks the height factor to the lowest bracket (0.6). Since bifacial panels are primarily used in ground-mount installations with 1.0–1.5m clearance, the default significantly underestimates rear-side gains for the target use case. The parameter exists in the calculation layer but is never plumbed through `handlers.py` or the frontend.
