# Building position fallback hardening and dark-theme conversion (v2)

This change fixes a building-position bug in the 3D viewer (`viewer.html`) and converts `energy-profile.html` to the dark Solar Pro theme. The viewer fix ensures hidden inputs `bud-x`/`bud-z` always carry valid coordinates — falling back to `-16.2`/`13.5` only when the source value is literally empty or non-numeric, not when it's zero. The energy-profile conversion replaces all light backgrounds, blue accents, and white tables with the dark-surface + amber-accent scheme already used by `report.html`, and corrects user defaults (250W base, G11f_dynamiczna tariff, 16kWh battery enabled). Watch for: no blocking concerns remain after the v1 fixes.

## High-level view

The viewer's position-fallback logic now distinguishes "input is empty" from "input is zero" — the v1 bug where `v === 0` triggered the fallback is gone. Both the `budynekConfig` localStorage save and the simulation payload builder use the same pattern: trim the input string, check for empty, only then parse. `przeliczFallback()` similarly writes hardcoded defaults only when fallback inputs have empty `.value`, so zero coordinates pass through correctly.

The energy-profile dark-theme conversion is scoped entirely to a `<style>` block that overrides colors, borders, backgrounds, and adds focus states for inputs. The shared `style.css` provides the dark body gradient, so no structural conflict arises. Default form values now match the user's configuration: 250W base consumption, G11f_dynamiczna tariff pre-selected, battery checkbox checked with `display:block` on the options container, and sell-hour slider defaulting to 23.

## Position fallback: empty-string detection

The `budynekConfig` save uses an IIFE that trims the input value and checks for empty string before parsing:

```js
x: (function() { var s = document.getElementById('bud-x').value.trim(); if (s === '') return -16.2; var v = parseFloat(s); return isNaN(v) ? -16.2 : v; })(),
```

The simulation payload builder mirrors this with a multi-step fallback that also checks `.value.trim() === ''` before consulting the fallback input. The `przeliczFallback()` function — called on page load when no parcel vertices exist — writes `-16.2`/`13.5` strings directly into the hidden inputs when the fallback inputs are empty, so the downstream save/simulate paths always find a parseable value.
