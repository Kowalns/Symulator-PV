# Single-plane layout and real RCE prices from PSE API (v2)

All four issues from the v1 review have been addressed. The SSL context now carries a detailed comment explaining why CERT_NONE is necessary (incomplete certificate chain on PSE's server). The vestigial `liczba_kolumn` field is removed from `InstallationConfig`. The PSE fetcher retries failed days (2 attempts, 1 second delay) and accumulates skipped dates into a printed summary rather than silently swallowing them.

The core changes are clean: the layout is correctly simplified from rows × columns to a single plane of N panels in one row, and the G11f tariff is now correctly modeled as a dynamic tariff (RCE hourly price + seller markup + G11f distribution fees) rather than the previous incorrect flat `1.0091 zł/kWh`. A committed cache of 783 days of real PSE data (2024-06-14 through 2026-08-05, including 784 negative-price hours) backs the pricing model. All 250 tests pass.

Watch for: nothing blocking remains.

**Verdict**: APPROVED

## High-level view

The layout simplification removes three fields (`odstep_miedzy_rzedami_cm`, `liczba_kolumn`, `liczba_rzedow`) from the dataclass, API handlers, frontend sliders, and tests in one consistent sweep. The single-loop layout algorithm computes panel positions along the X axis with uniform spacing, accurately representing the user's scenario: one tilted plane of panels side by side, no inter-row shading to calculate.

The G11f tariff correction changes the `typ` from `"stala"` to `"dynamiczna"` in `tariffs.json`, adds `narzut_sprzedawcy_zl_kwh`, and unifies the `oblicz_cene_kupna` code path so both `G11f` and `dynamiczna` flow through the same RCE + fees formula — distinguished only by the distribution rate (0.2180 vs 0.3485 zł/kWh).

The RCE module adds a full PSE API client (day-by-day 15-minute data fetch, aggregation to hourly averages, JSON cache, lazy-loaded global), with graceful fallback to the original synthetic 12×24 table when cache is unavailable. The retry logic (configurable `liczba_prob`, default 2 with 1s sleep) and printed summary of skipped days address the original reliability concern adequately for a cache that's populated offline and committed.
