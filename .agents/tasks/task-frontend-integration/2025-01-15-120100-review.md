# Multi-step PV wizard with backend integration and tariff restructuring

This change transforms isolated HTML pages into a connected 3-step wizard (3D viewer → energy profile → report) using localStorage as the cross-page state bus. The backend simplifies the installation model from a row/column grid to a single-plane layout, restructures tariff definitions to reflect real Energa 2026 pricing (separating G11f_dynamiczna and G11_dynamiczna), adds real RCE price caching from PSE API, and extends the panel performance model with POA irradiance correction. All five issues from the v1 review have been addressed: building dimensions are now editable and pre-filled from STL bounding box, location fields are exposed in the form, the report page guards against missing step 1 data, and step 2 completion is detected immediately after profile computation.

Watch for: The G11f_dynamiczna tariff label in the energy-profile dropdown displays a fixed "~1.01 zl/kWh" price which contradicts its dynamic nature — users may not understand this is an hourly-varying price (confirmed). SSL certificate verification is disabled for PSE API calls, which is documented and justified but persists in production code (confirmed).

**Verdict**: APPROVED

## High-level view

The v1 issues are resolved cleanly. Building dimensions flow from STL bounding box through `window.__stlBoundingBox` into editable form fields, which the shading payload reads at submission time. Location fields (lat/lon) sit in the sidebar and feed both the shading call and the installation config saved to localStorage. The report page now distinguishes three states: both steps complete (auto-generate), only step 2 complete (show explicit warning that production data is estimated), and nothing present (show links to earlier steps).

The energy profile service fixes a 24x over-counting bug in heat pump consumption by normalizing the hourly profiles to sum to 1.0 and removing the spurious `* 24.0` multiplier. The new `test_energy_profile.py` suite guards against regression on this exact error.

## Tariff label inconsistency

In `frontend/pages/energy-profile.html` line ~305:

```html
<option value="G11f_dynamiczna">G11f dynamiczna - nizsza dystrybucja, wyzsza oplata stala (~1.01 zl/kWh)</option>
<option value="G11_dynamiczna">Oferta dynamiczna - cena godzinowa wg RCE</option>
```

Both G11f_dynamiczna and G11_dynamiczna are dynamic tariffs — the only difference is distribution charges. But only the second option's label communicates hourly variability. The "~1.01 zl/kWh" figure for G11f_dynamiczna is presumably an average, but a user comparing G11 at "~1.14 zl/kWh" to G11f at "~1.01 zl/kWh" will treat both as flat rates and miss that G11f_dynamiczna can swing from negative to >1.5 zl/kWh within a single day.

## Energy profile normalization fix

The `* 24.0` multiplier was producing 24x inflation of heat pump consumption because the hourly profile already distributes the daily total across 24 hours. With normalized profiles (sum = 1.0), the formula `(monthly_total / days) * hourly_weight` correctly yields the Wh consumption for one hour without any additional scaling. The test `test_250w_plus_5000_co_plus_2000_cwu` asserts the annual total stays within 8500-10500 kWh, which would catch the 24x regression (that bug produced ~182 MWh).
