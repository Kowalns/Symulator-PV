# PVGIS TMY integration with POA irradiance model

This change replaces a hardcoded monthly irradiance model with real hourly meteorological data from the PVGIS TMY API. It introduces a proper Plane-of-Array (POA) irradiance decomposition into beam, diffuse, and ground-reflected components, a NOCT cell temperature model driven by TMY ambient temperatures, and physics-correct shading that only blocks the beam component. The old model is retained as a fallback when TMY data is unavailable. A new POST endpoint lets the frontend pre-fetch TMY data into a file cache before running simulations.

Watch for: The shading simulation endpoint silently attempts a live PVGIS API call (30s timeout) if no cache exists, which can make it unexpectedly slow (confirmed). The cache has no TTL or invalidation mechanism, so stale TMY files persist indefinitely (confirmed). The cache key uses `round(lat, 2)` which can produce keys like `tmy_52_2_21_0.json` when trailing zeros are dropped by Python's float formatting, creating a subtle mismatch between separately-rounded coordinates (likely).

**Verdict**: APPROVED

## High-level view

The TMY service (`pvgis.py`) fetches 8760 hourly records from the PVGIS v5.3 endpoint, parses GHI/DNI/DHI/temperature/wind, and writes them to a flat JSON file cache keyed by rounded coordinates. The fetch is exposed to the frontend via `POST /api/tmy/fetch` and is also invoked implicitly during shading simulation if the cache is cold, making the shading endpoint's latency dependent on external API availability.

The POA model (`panel_performance.py`) decomposes irradiance into three physical components: beam via `DNI * cos(AOI)`, isotropic diffuse via `DHI * (1 + cos(tilt)) / 2`, and ground reflection via `GHI * albedo * (1 - cos(tilt)) / 2`. Shading reduces only the beam term, which means a fully shaded panel still produces energy from diffuse and ground — a meaningful behavioral difference from the old model where shading applied uniformly. The bypass-diode loss factor is scaled proportionally to beam's share of total irradiance, which departs from cell-level electrical modeling but avoids double-penalizing uniform diffuse.

Temperature now comes from TMY hourly values fed through the NOCT formula `T_cell = T_amb + (NOCT - 20) * G_POA / 800` instead of monthly averages with a fixed delta, coupling panel temperature to actual irradiance.

The frontend adds a "Pobierz dane pogodowe" button that fires a POST to `/api/tmy/fetch` and stores a summary in localStorage. The simulation itself doesn't read localStorage — it independently attempts to load cached TMY from disk, so the button's purpose is to warm the cache and give the user visual confirmation.

The test suite adds 24 tests including a validation test that asserts 900–1050 kWh/year for a 1 kWp system at 54°N/30°/south, confirming the model produces physically plausible output with real PVGIS data.

## Implicit API call in the shading simulation path

When `handle_shading_simulate` runs, it calls `pobierz_dane_tmy(szerokosc_geo, dlugosc_geo, uzyj_cache=True)`. The `uzyj_cache=True` flag means "check cache first, then fetch from the network." If the user hasn't clicked the TMY button (or the cache file is missing), the simulation handler blocks on a 30-second PVGIS API call. On timeout or error it gracefully falls back, but the user experiences an unexplained delay on what should be a local computation.

The intent of the design — separate "fetch" button then "simulate" — breaks down because the simulate path doesn't restrict itself to cache reads. A simple fix: add a `tylko_cache=True` parameter that skips the network call and returns None immediately on cache miss, or split the function into `wczytaj_tmy_z_cache()` and `pobierz_tmy_z_api()`.

## Cache key formatting and perpetual cache

The cache key derives from `f"{round(lat, 2)}"`. Python's default float-to-string drops trailing zeros: `round(52.20, 2)` formats as `"52.2"`, producing `tmy_52_2_...`. This is deterministic within the same Python process, so it won't cause cache misses *within this application*, but it means the on-disk filename doesn't match a naive expectation of two-decimal precision and creates fragility if cache files are shared between systems or generated externally.

The cache never expires. TMY data from PVGIS is stable (it's a statistical composite of 20 years of satellite data), so a long TTL is acceptable — but there's no mechanism to recover from a corrupted write (disk full, partial JSON). A corrupted cache file would permanently return `None` from `_wczytaj_cache_tmy` due to `json.JSONDecodeError`, causing silent fallback to the old model with no user-visible indication that the cache is broken.

## Shading applies only to beam — bypass diode interaction

The bypass-diode coefficient is scaled by `udzial_beam / irradiancja_efektywna`, so when beam is fully blocked the bypass factor becomes 1.0 (no electrical mismatch penalty from diffuse). When beam is partially blocked, the bypass penalty scales with beam's share — an approximation, since real bypass activation depends on *which* cells are shaded, not the ratio of beam to total. The code comment in `_oblicz_roczna_produkcje_tmy` could be more explicit about *why* uniform diffuse doesn't trigger bypass (photocurrent is equal across all cells when illumination is uniform, so no cell becomes reverse-biased).

## Frontend integration gaps

The `localStorage.setItem('tmy_fetched', ...)` value is never consumed by any downstream code — it's a dead write. The simulation reads disk cache server-side regardless of localStorage state.

The `ostrzezenie` field returned by `handle_shading_simulate` when TMY is absent is not rendered anywhere in the frontend. The `zrodlo_danych` field (`"tmy"` vs `"fallback"`) is similarly invisible to the user. Both could be surfaced in the simulation results page to indicate data quality.

## Test coverage gaps

Not tested: behavior when PVGIS returns an HTTP 429 (rate limit) or when the response JSON structure changes. Not tested: the latency impact of the implicit API call in `handle_shading_simulate` when cache is cold. Not tested: cache file corruption recovery (truncated JSON on disk).
