# Ground-mount PV simulator: shading engine, economics, and reporting

This change builds a full photovoltaic installation simulator on top of a minimal MVP skeleton. It adds a solar position algorithm, hourly shadow casting from a building onto ground-mounted panels, bypass diode and half-cut cell modeling, power optimizer comparison, an hour-by-hour economic engine (Energa tariffs + RCE spot prices), battery sizing, scenario comparison, and annual/monthly reporting with optimization recommendations. The frontend gains a Three.js 3D viewer with STL building import, ULDK parcel boundary integration, and panel layout visualization. All backend code is stdlib-only Python 3.9; frontend is vanilla JS with Three.js from CDN. 243 tests pass.

Watch for: shadow projection uses a bounding-box approximation that over-estimates shading when the sun is off-axis (confirmed); the `oblicz_mismatch_stringa` function claims bypass diodes help but doesn't actually model them reducing mismatch loss (confirmed); battery charging applies roundtrip efficiency on charge but not on discharge (confirmed); the ULDK proxy does basic allowlisting but passes user-controlled values directly into a URL without encoding (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The shading engine projects the building's top vertices onto the ground plane along the solar vector and takes the axis-aligned bounding box of those projections. This overestimates the shadow polygon for any sun position that isn't due south, which inflates shading losses for morning and afternoon hours. The simplification is declared intentional (performance on stdlib only) but the magnitude of the error grows with low-elevation oblique angles, exactly the hours where partial shading matters most.

The panel performance model chains irradiance, temperature coefficient, bypass diode logic, and half-cut topology into a single multiplicative formula. The half-cut model correctly keeps one half producing when only the other is shaded, and bypass sections drop proportionally. However, the optimizer/string mismatch model uses `min(wspolczynniki)` as the string output even though the prose describes bypass diodes reducing the penalty, meaning optimizer ROI calculations overstate the gain.

The economic engine iterates 8760 hours, dispatching surplus to battery or grid sale, and deficit to battery discharge or grid purchase. Battery state management applies `sprawnosc` (roundtrip efficiency) only at charge time, so stored energy is already discounted. This is internally consistent but over-values discharge by not modeling any discharge-side loss. The explicit guard against grid-to-battery arbitrage is correct for the Polish net-billing regime.

RCE price data is a static 12x24 table of representative hourly spot prices. This is adequate for comparative scenario analysis but limits the value of the "dynamic tariff" scenario to showing shape effects, not absolute savings.

The ULDK proxy allowlists parameter keys but does not URL-encode the values before concatenating them into the upstream URL, enabling parameter injection against the remote service.

## Issues (5)

<details>
<summary>Issues (5)</summary>

1. **Shadow bounding-box overestimation** — The shadow polygon is reduced to an AABB, which overstates panel coverage for oblique sun angles. Replace with a proper 2D convex hull of the projected points (only 8 points, so even a naive O(n^2) hull is cheap).
2. **Mismatch model ignores bypass diodes** — `oblicz_mismatch_stringa` returns `min_wsp` as the string output. The docstring says bypass diodes reduce the penalty, but the code doesn't implement that path. Either model bypass relief or remove the misleading comment.
3. **Battery efficiency applied asymmetrically** — `magazyn_stan += ladowanie * sprawnosc` on charge, but discharge subtracts raw Wh (`magazyn_stan -= rozladowanie`). Apply `sqrt(sprawnosc)` to each direction, or apply the full loss on discharge instead of charge, to model roundtrip correctly.
4. **ULDK proxy URL injection** — User-supplied values from `parse_qs` are concatenated into the ULDK URL without `urllib.parse.quote`. A crafted `id` parameter (e.g., containing `&` or `#`) can inject extra parameters or truncate the URL. Use `urllib.parse.urlencode` to build the query string.
5. **No DST handling in solar position** — `strefa_czasowa` defaults to 1.0 (CET) year-round. Polish summer time (CEST = +2) shifts sun position by one hour for March-October, causing systematic azimuth error during the majority of the production year. Accept a per-month or per-date flag.

## Shadow projection geometry

The core shading function `_oblicz_cien_budynku_na_gruncie` projects the four top vertices of the building box along the solar vector to the ground, then combines them with the four bottom footprint corners to form the shadow polygon. But `_oblicz_zacienienie_panela` intersects panels against `_bounding_box_cienia(punkty)` — the axis-aligned bounding box of those 8 points.

When the sun is at azimuth 120 (east-southeast), the projected shadow polygon is a slanted parallelogram, but its AABB can be substantially larger. For a 10m-wide, 8m-tall building at 15-degree elevation, the true shadow polygon might cover 35m of Z extent but only 12m of X extent at the actual polygon edge; the AABB assigns the full X range across the entire Z range, inflating the shadow area.

The per-panel intersection is already rectangle-vs-rectangle (fast), so replacing the AABB with a proper convex hull and doing point-in-polygon (or polygon-clipping against the panel rectangle) would fix accuracy without significant cost — there are only 8 hull points and typically 10-20 panels.

```
Current: shadow = AABB(project(top_verts) + bottom_verts)
Correct: shadow = convex_hull(project(top_verts) + bottom_verts)
         per-panel area = polygon_intersection(shadow, panel_rect)
```

## String mismatch vs bypass diodes

In `backend/services/optimizer.py`, `oblicz_mismatch_stringa`:

```python
# Realistyczny model: moc = min_wsp (najgorszy przypadek)
return min_wsp
```

This models a string as if the weakest panel forces all panels to its current level. In reality, bypass diodes allow the shaded panel's substring to be skipped, so the string loses only 1/N_bypass of the shaded panel's contribution, not the entire string's output. The `panel_performance.py` module correctly models bypass at the individual panel level (subtracting 1/3 per activated bypass section), but the optimizer module doesn't compose these — it re-derives mismatch from raw shading coefficients and uses the minimum.

The consequence: `porownaj_z_bez_optymalizatorow` overstates the without-optimizer loss, making optimizer ROI calculations overly optimistic. `czy_optymalizatory_uzasadnione` then reports shorter payback periods than reality.

## Battery efficiency accounting

In `economics.py`, the charging path:

```python
magazyn_stan += ladowanie * sprawnosc
```

And the discharging path:

```python
magazyn_stan -= rozladowanie
```

If a 10 kWh battery has 95% roundtrip efficiency, the standard industry split is `sqrt(0.95)` on each leg (~97.5% charge, ~97.5% discharge), or equivalently 95% on one leg and 100% on the other. The current code applies the full 95% at charge time and none at discharge. This means: if you charge 5 kWh, you store 4.75 kWh, and when you discharge 4.75 kWh, you deliver 4.75 kWh to the home. The actual deliverable should be `4.75 * 0.975 = 4.63 kWh` (or equivalently, `5 * 0.95 = 4.75 kWh` if all loss is applied once). Since the code applies the full roundtrip loss at charge, it is internally consistent as a roundtrip model — but it inflates the apparent value of discharged energy by the discharge-side loss.

The practical impact is small (~2.5% of battery throughput) but systematically favors battery scenarios in comparisons.

## ULDK proxy parameter injection

```python
uldk_params.append(f"{key}={value}")
uldk_url = f"https://uldk.gugik.gov.pl/?{('&').join(uldk_params)}"
```

`value` comes from `parse_qs(query_string)` which URL-decodes it. If a user sends `id=141201_1.0001.6509%26result=teryt`, the `value` after `parse_qs` is `141201_1.0001.6509&result=teryt`, which injects an extra `result` parameter into the upstream request. The fix is to use `urllib.parse.urlencode(params_dict)` instead of manual string concatenation.

## Solar position DST gap

`get_solar_position` accepts `strefa_czasowa: float = 1.0`. Poland uses CET (+1) in winter and CEST (+2) from last Sunday of March to last Sunday of October. The caller never adjusts this, so from April through October the calculated solar time is off by one hour — the algorithm thinks the sun is at its noon position at 13:00 local time rather than 12:00. This shifts all shading calculations and production estimates by one hour during the most productive months.

For a shading simulator, a one-hour azimuth error at low elevation can mean the difference between a panel being in shadow or in sun. The hourly resolution masks some of this (an hour-boundary shift), but the systematic offset means summer afternoon shading is attributed to the wrong hour.

## Panel database completeness

All 12 panels in the database use `"technologia": "half-cut"` and `"liczba_sekcji_bypass": 3`. The code paths for `technologia == "standard"` (no half-cut) exist and are tested but cannot be exercised through the database — every panel benefits from half-cut logic. If the intent is to support comparison between technologies, at least one standard-cell panel should be included.

## Test coverage shape

The 243 tests cover solar position, shading geometry, bypass/half-cut logic, optimizer comparisons, installation layout, economics, reporting, and the ULDK proxy. What is not tested: the full end-to-end pipeline from `handle_shading_simulate` through to report generation (the API handler integration test is absent); the scenario comparison with a real battery model; the `generuj_rekomendacje` function; and the frontend modules (expected given vanilla JS without a test framework).
