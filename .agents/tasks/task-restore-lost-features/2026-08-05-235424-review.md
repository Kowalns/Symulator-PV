# PV simulator: v2 review after v1 fixes

All five issues from the v1 review have been addressed. The shadow engine now computes a convex hull and clips panels via Sutherland-Hodgman polygon intersection. The string mismatch model estimates bypass diode relief by section-counting. Battery efficiency is split symmetrically with `sqrt(sprawnosc_roundtrip)` on each leg. The ULDK proxy builds the outbound URL through `urllib.parse.urlencode`. The solar position module implements `czy_czas_letni()` with correct Polish CEST transition rules.

Watch for: the DST fix is unreachable from the production API because both `oblicz_zacienienie_godzinowe` and the API handler default `strefa_czasowa` to `1.0`, so the `czy_czas_letni` path never fires unless the caller explicitly passes `None` (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The `czy_czas_letni` function correctly identifies CEST boundaries, but `get_solar_position` auto-detects DST only when `strefa_czasowa is None`. The two production call sites default this parameter to `1.0`, so the fix only activates in isolation or when a caller explicitly passes `None`. March-through-October solar positions are still computed with CET year-round in practice.

The old AABB function `_bounding_box_cienia` survives as dead code after the switch to polygon clipping. No callers remain.

## DST fix is wired but not activated

`get_solar_position` invokes `czy_czas_letni` when `strefa_czasowa is None`:

```python
if strefa_czasowa is None:
    if czy_czas_letni(rok, miesiac, dzien, godzina):
        strefa_czasowa = 2.0
    else:
        strefa_czasowa = 1.0
```

But the production pipeline passes a concrete float:

```python
# handlers.py line 473
strefa_czasowa = float(lok.get("strefa_czasowa", 1.0))

# shading.py line 526
def oblicz_zacienienie_godzinowe(..., strefa_czasowa: float = 1.0):
```

The type annotation `float` (not `Optional[float]`) further obscures the intent. March-through-October solar positions are computed as CET, introducing a one-hour timing error during 7 months of the year — the exact problem v1 flagged, now implemented but not plumbed through.

Fix: change both defaults to `None`, change the type to `Optional[float]`, and let `get_solar_position`'s internal DST logic handle it.
