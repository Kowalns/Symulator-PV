# Expert Panel Review: PV Simulator Post-Fix Verification

Symulator przeszedl 4 rundy review i commit 3161ba7 naprawil 11 zgloszonych bledow. Niniejszy przeglad weryfikuje poprawnosc tych napraw i identyfikuje nowe problemy. Wszystkie 386 testow przechodzi. Pozostaja trzy istotne problemy wpływajace na dokladnosc wynikow.

**Watch for:** (1) Sciezka z optymalizatorami uzywa wspolczynnika bypass (elektrycznego) jako mnoznika transmisji beam (optycznego) — zawyza produkcje zacienionych paneli o 10-20% [confirmed]. (2) Net-billing z depozytem przy ujemnych cenach moze dac ujemny depozyt, ktory na koniec roku generuje bezsensowne wartosci forfeit/zwrot [confirmed]. (3) Model bypass przy calkowicie zacienionym panelu (min_wsp=0) daje wynik=0, nie odzyskujac zadnej energii z reszty stringa [confirmed].

**Verdict**: NEEDS_CHANGES

## High-level view

Model bypass diod (oblicz_mismatch_stringa) poprawnie interpoluje miedzy minimum a srednia dla czesciowego zacienienia, ale degeneruje do zera gdy najgorszy panel jest calkowicie zacieniowany — w rzeczywistosci bypass ominalby ten panel i reszta stringa produkowalaby normalnie. To zaniża produkcje stringow z jednym martwym panelem.

Sciezka z optymalizatorami w oblicz_roczna_produkcje_instalacji stosuje wspolczynnik wyjsciowy bypass (wartosc 0.667 dla 1/3 zacienienia) jako mnoznik przepuszczalnosci wiazki beam, zamiast uzyc fizycznego stopnia zacienienia. Skutek: panel z 50% fizycznym cieniem traci tylko 33% beam, bo bypass factor > physical transmittance.

Model ekonomiczny net-billing z depozytem pozwala na ujemna wartosc depozytu (przez iniekcje przy ujemnych cenach RCE). Na koniec roku oblicza 80% forfeit i 20% zwrot z ujemnej wartosci, generujac logicznie nonsensowne wyniki. Z typowymi danymi RCE i marza 0.03 PLN/kWh wystepuja jedynie 3 godziny miesieczne z ujemna cena — ryzyko niskie ale nie zerowe.

Antyarbitraz jest szczelny: sciezka "sprzedaz" limituje sprzedaz do magazyn_stan_pv, sciezka "autokonsumpcja" ogranicza nadwyzke_uwolniona do udzialu_pv * energia_dostarczona. Nie istnieje sposob monetyzacji energii sieciowej w magazynie.

<summary>Issues (5)</summary>

1. **Bypass model przy min_wsp=0** — Gdy najgorszy panel ma wsp=0 (calkowite zacienienie), oblicz_mismatch_stringa zwraca 0.0 (caly string martwy). W rzeczywistosci bypass ominalby ten panel, reszta stringa produkuje normalnie (~(N-1)/N mocy). Popraw: jesli efektywny_wsp_bypass=0, wynik powinien byc (suma_reszty/n) * wsp_korekcji zamiast 0.
2. **Optimizer path: wsp_zacien jako beam multiplier** — W oblicz_roczna_produkcje_instalacji (z_optymalizatorami=True), `poa["beam"] * wsp_zacien` uzywa wartosci bypass (0.667) zamiast fizycznego stopnia zacienienia (0.5). Popraw: uzyj `poa["beam"] * (1 - stopien_zacienienia)` jak w per-panel path, a bypass zastosuj jako oddzielny mnoznik mocy DC.
3. **Net-billing ujemny depozyt** — depozyt_stan moze byc ujemny po iniekcji przy ujemnych RCE. depozyt_przepadlo i depozyt_zwrot obliczane z ujemnej bazy daja bezsensowne wartosci. Popraw: `depozyt_stan = max(0, depozyt_stan)` przed obliczeniem rocznego rozliczenia.
4. **Mismatch na poa_total zamiast na mocy** — Sciezka bez optymalizatorow mnozy `poa_total * wsp_mismatch` i oblicza temperature z tej zredukowanej irradiancji. Mismatch jest efektem elektrycznym, wiec temperatura powinna byc obliczona z pelnym POA. Wplyw: < 1% zawyzona produkcja (nizsza temp -> lepszy wsp_temp).
5. **Brak clamp na autokonsumpcja_kwh** — Przy rozladowaniu magazynu (bilans >= 0) kod odejmuje nadwyzka_uwolniona od autokonsumpcja_kwh. Przy ekstremalnych warunkach moze to dac ujemna autokonsumpcje miesieczna. Dodaj `max(0, ...)`.

## Weryfikacja napraw (Bug #1-#11)

### Bug #1: Bypass model — POPRAWNY ale z edge case

Formula `wynik = min_wsp + wsp_odzysku * (wynik_idealny - min_wsp)` z ograniczeniem miedzy min_wsp a srednia dziala poprawnie dla czesciowego zacienienia.

Gdy `min_wsp = 0.0`:
```
stopien_zacienienia_max = 1.0
zacienione_sekcje = 3 (wszystkie powyżej progu 15%)
efektywny_wsp_bypass = 0/3 = 0
wynik = 0 + 0 * (cokolwiek - 0) = 0
```
String z 10 paneli (9 niezacienionych + 1 martwy) daje wynik 0 zamiast oczekiwanego ~0.9. Bypass w tym scenariuszu omija caly martwy panel — prad stringa plynie przez 9 pozostalych paneli (nie jest ograniczony), a napiecie spada o 1/10 (martwy panel nie generuje napiecia). Oczekiwana moc stringa: ~(N-1)/N * srednia_reszty.

### Bug #2: Albedo w POA — POPRAWNY

### Bug #3: Diffuse/ground niezalezne od cienia — CZESCIOWO POPRAWNY

Kod:
```python
efektywna_irr = poa["beam"] * wsp_zacien + poa["diffuse"] + poa["ground"]
```
Diffuse i ground nie sa blokowane — poprawne. Ale `wsp_zacien` pochodzi z `oblicz_wspolczynnik_zacienienia()` ktora zwraca wspolczynnik MOCY (electrical), nie fizyczny procent blokowania beam (optical). Dla standard tech z 1/3 sekcji aktywnej bypass, 50% fizyczny cien daje wsp_zacien=0.667 (powinno byc 0.5 dla beam multiplier).

Per-panel path poprawnie rozdziela: `beam * (1-stopien)` + osobny mnoznik bypass na moc.

### Bug #4: Anti-arbitraz — POPRAWNY

Sprawdzono trzy sciezki:
- Sprzedaz: `do_sprzedazy_raw = min(magazyn_stan_pv, moc_rozlad)` — tylko PV

- Autokonsumpcja z nadwyzka: `nadwyzka_uwolniona = min(energia_dostarczona * udzial_pv, zuzycie)` — przy udzial_pv=0 nadwyzka=0

## Optimizer path: beam vs electrical factor (szczegolowa analiza)

W `oblicz_roczna_produkcje_instalacji` z `z_optymalizatorami=True`, linie 988-993:

```python
wsp_zacien = zacienienia_per_panel[idx]  # from oblicz_wspolczynnik_zacienienia
efektywna_irr = (
    poa["beam"] * wsp_zacien +
    poa["diffuse"] +
    poa["ground"]
)
```

`oblicz_wspolczynnik_zacienienia` dla standard tech z 50% cieniem:
- stopien=0.5, sekcje_zacienione=[True, False, False], bypass=1
- Zwraca: `1.0 - 1/3 = 0.667` (bo 1 sekcja bypass aktywna)

Efekt: `beam * 0.667` vs poprawne `beam * 0.5`. Przy poa_beam=600 W/m2 roznica to 100 W/m2 dodatkowej irradiancji. Dla panela 550W to ~55W zawyzona moc (10% wiecej).

W per-panel path (`_oblicz_roczna_produkcje_tmy`) rozdzielenie jest poprawne:
1. `beam * (1.0 - stopien)` — fizyczna transmisja optyczna
2. `wsp_zacien_bypass` — elektryczny efekt bypass (oddzielny mnoznik)
3. Bypass modyfikuje tylko czesc beamowa proporcjonalnie: `1.0 - udzial_beam * (1 - wsp_zacien_bypass)`

Naprawa: w optimizer path potrzebny jest `stopien_zacienienia` (nie wsp_zacien) jako beam multiplier. Trzeba zmienic zbieranie danych z `oblicz_wspolczynnik_zacienienia(pz)` na bezposredni `pz.stopien_zacienienia` dla beam, a wsp_zacien zastosowac na moc DC.

## Net-billing deposit z ujemnymi cenami

```python
wartosc_nadwyzki = (nadwyzka / 1000.0) * cena_sprzedazy  # negative if cena < 0
depozyt_stan += wartosc_nadwyzki                          # can go below zero
```

Na koniec roku:
```python
depozyt_przepadlo = depozyt_stan * 0.80  # -50 * 0.80 = -40 (nonsensical)
depozyt_zwrot = depozyt_stan * 0.20       # -50 * 0.20 = -10 (nonsensical)
```

Rozwiazanie: przed rozliczeniem rocznym `depozyt_stan = max(0.0, depozyt_stan)`. Alternatywnie: traktuj ujemna wartosc_nadwyzki jako koszt (dodaj do koszt_z_portfela) zamiast odejmowac od depozytu.

## Przeliczenia jednostek

- RCE: PLN/MWh → /1000 → PLN/kWh. Kupno: +VAT 23%. Sprzedaz: netto. Zweryfikowane numerycznie.
- Taryfa dynamiczna: CTGE*1.23 + stale_brutto. Wynik code (0.2249) = wynik formula (0.2248). Rounding only.
- Produkcja Wh/h → /1000 → kWh. Poprawne wszedzie.
